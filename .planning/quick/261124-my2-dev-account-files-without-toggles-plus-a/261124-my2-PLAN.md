<objective>
Three small changes to the serial-mail sample, from the task description (items D-01, D-02, D-03):

- D-02: a user put the actual client secret into `secretEnv=` and got "the environment variable it names is not set or is empty", which did not tell them what was wrong. When `secretEnv` or `certificate.passwordEnv` names an unset or empty variable and its value does not look like a variable name, the pre-flight line adds a fixed hint. The value is never printed.
- D-01: the development account no longer has a toggle line. `dev-account.properties` is the certificate variant. The new committed `dev-account-secret.properties` is the client-secret variant. Each header names its credential and the other file.
- D-03: every doc that told the user to exchange lines now gives two `--account` choices instead.

Purpose: switching credentials needs no file edit, and a secret pasted into the wrong key gets a message that says what is wrong without leaking it.
Output: one changed message helper, one new properties file, five new tests, one adjusted test expectation, four updated docs.
</objective>
