# Phase 6 Plan 02: Inline problems in pre-flight, the example logo and the phase gate

## Phase Goal

A campaign author can put images into an optional `inline/` directory. The dry run shows them in the rendered mails, and every sent mail carries them inline.

This plan's slice: Plan 06-01 made inline images travel and show in the dry run. Task 1 (tracer) reports every inline defect in the pre-flight report, with the account and campaign findings, exit 2, nothing written (CLI-16). Task 2 gives the shipped example campaign a tiny generated `inline/logo.png` that its HTML shows at the top (CLI-18), proves it in the dry run and on the Graph wire, and runs the phase gate.

## Acceptance Criteria

- [ ] Pre-flight reports each inline problem (cid: with no image, image with no cid:, same base name, non-image file, file name giving an invalid content ID) once, in the same report as the other findings, exit 2, nothing sent, no out/, no journal.
- [ ] The dry run of the example campaign writes five mails that each show `inline/logo.png`; Graph receives the logo as the only inline attachment; sent HTML keeps `cid:logo`.
- [ ] The three CI commands are green on JDK 21; core and POMs unchanged; two commits with the maintainer identity, none pushed.
- [ ] Phase 6 is verified-complete only after the owner's Temurin 17 CI run of the pushed Phase 6 commits is green (human-check).

Choices (Claude's discretion per 06-CONTEXT.md, recorded here; the SUMMARY lists them for owner review):
- Type and ID checks through a probe mail, not a copied content-type table: the core falls back to the host's `Files.probeContentType` for extensions outside its table (06-RESEARCH ran `a.webp` to `image/webp`), so a copied table would disagree; the core API is not widened.
- A file is probed once, so a file with two defects (for example `my notes.txt`, a bad name and not an image) shows the first one the core finds; the second shows after the fix, as `build()` does (Phase 5 D-13).
- Report order: `inline/ cannot be listed` if listing fails, then file by file in name order (the probe problem, then a same-ID problem), then each `cid:` with no image in order of first appearance, then each image with no reference in name order. The inline block sits after the `attachments/` listing, so it comes before the CSV and placeholder findings, and runs even when another file is missing (like `attachments/`); the template cross-check is skipped when `body.html` is missing.
- The cross-check counts every listed file's ID for "has no image", so a non-image or badly named file does not also cause a "no image" line; "no reference" applies only to files that passed the probe (images).
- Messages: `inline/NAME: <core message>`, `inline/NAME: same content ID as inline/FIRST (cid:ID)`, `body.html: cid:ID has no image in inline/`, `inline/NAME: no cid:ID reference in body.html`. IDs read from the template are shown whole (template author input, not recipient data; Phase 5 D-14).
