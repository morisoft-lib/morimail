# Phase 6 Plan 01: Inline images through the serial-mail sample (tracer first)

## Phase Goal

A campaign author can put images into an optional `inline/` directory. The dry run shows them in the rendered mails, and every sent mail carries them inline.

This plan's slice: the tracer takes one `inline/logo.png` from the campaign directory through `Campaign.read`, the pre-flight build loop and `Mail.Builder.inline` to `recording` (the sent mail keeps `cid:logo`), and through the dry run to `out/inline/logo.png` with the written HTML pointing at it. The expansion task pins the edges: file names that need percent-encoding, the any-case prefix and the bare `cid:`, `--limit`, reruns, hidden-only `inline/` and the order of several images. Plan 06-02 adds the pre-flight scan (CLI-16), the example campaign logo (CLI-18) and the phase gate.

## Acceptance Criteria

- [ ] A campaign with `inline/` sends every mail with each file as an inline image under the file name without its last extension, and the sent HTML keeps `cid:`.
- [ ] The dry run copies each image once into `out/inline/`, prints an `inline:` line, and every written HTML file points at the copies by percent-encoded relative path.
- [ ] A campaign without `inline/` behaves exactly as in v0.1.0: all existing sample tests pass unchanged.
- [ ] `./mvnw -B -ntp verify` is green, the core and the POMs are unchanged, two commits with the maintainer identity; Claude pushes none.
- [ ] Task 3: the owner has pushed the 06-01 commits and confirmed that the Temurin 17 CI run is green in all three steps (verify, scoped release build, offline build) before Plan 06-02 Task 1 starts.
