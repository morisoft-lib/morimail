# Phase 1 Plan 04: Walking skeleton, part 3 — send a plain mail through a recording account

## Phase Goal

**As a** Java developer, **I want to** build a templated mail and send it through a Mailer account, **so that** the core contracts are proven before any real transport.

This plan completes the Walking Skeleton (see `.planning/phases/01-library-core/SKELETON.md`): the thinnest send path from `Mail.using(..)` through `Mailer`, `MailAccount` and the `ServiceLoader` registry into the `recording` test transport, shipped in the test-jar and consumed by the sample module. `SendThroughRecordingTest` and `RecordingTestJarSmokeTest` are the skeleton's end-to-end acceptance gate; the expansion plans 01-05 (templates) and 01-06 (failures and configuration errors) start only after they pass. The import-rule and thread-safety guards land here, as soon as the core they guard is complete.

## Acceptance Criteria

- [ ] A plain-text mail goes from `Mail.using(..)` through `Mailer.of(account).send(mail)` into `RecordingTransport.sent()` with the account's `defaultFrom` applied, in the library and in the sample module, in the default and the release build.
- [ ] The import-rule test and the thread-safety-Javadoc test fail the build when their rule is broken (proven by mutation).
