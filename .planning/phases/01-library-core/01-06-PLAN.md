# Phase 1 Plan 06: Failure categories, scripted failures and configuration errors

## Phase Goal

**As a** Java developer, **I want to** build a templated mail and send it through a Mailer account, **so that** the core contracts are proven before any real transport.

This plan's slice: a test author scripts transient, permanent, sender-rejected and auth-required failures on the `recording` transport and sees each one surface from `Mailer` with its category; a misconfigured classpath or account fails at build time with a message that says what to fix; and one `Mailer` is safe to share between threads. It builds on the walking skeleton (plans 01-01, 01-03 and 01-04) and runs in parallel with plan 01-05, sharing no file.

## Acceptance Criteria

- [ ] `failNext`, `failFor` and `failValidation` script every failure category, and `Mailer` surfaces each with its type, without retrying.
- [ ] Duplicate ids, blank ids, broken providers, unknown transports, unknown accounts and bad `defaultFrom` values fail with the documented unchecked or checked exception.
- [ ] The concurrency test passes with 8 threads and 400 sends.
