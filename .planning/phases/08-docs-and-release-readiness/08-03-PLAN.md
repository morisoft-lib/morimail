# Phase 8 Plan 03: stop step 5 deploys at a SNAPSHOT version (gap G-08-2)

## Phase Goal

A developer reading the README and docs can use inline images, and the build is ready for the owner to release 0.2.0.

This plan's slice is DOCS-06: the owner can release from docs/release.md. In UAT test 2 the owner reached a deploy while the POMs still read 0.2.0-SNAPSHOT. central-publishing-maven-plugin 0.12.0 sends a SNAPSHOT build to Central's snapshots repository, and it uploads unless `-DskipUpload` is set. The namespace has no snapshot publishing, so the result was HTTP 401 and nothing was stored. The doc had no guard, and its SNAPSHOT note described the plugin wrongly. This plan corrects step 5 of the doc and nothing else.

- [ ] Nothing outside step 5 changed, both deploy lines are unchanged, and no build input changed since the release commit 2c4ea80.
- [ ] `./mvnw -B -ntp verify` is green on a git-archive copy of the fix commit. The commit holds docs/release.md only, made as the maintainer with the trailer, and not pushed.

Choices (Claude's discretion, recorded here):
- The guard is chained to the deploy with a trailing `&&` at the end of its own line, inside the deploy's fenced block. A separate check line or block cannot stop a deploy that is pasted after it, and `exit` would close the owner's terminal. The trailing `&&` makes the shell read the next line as part of the same command, so the deploy line stays a whole, unchanged line (D-13, and the 08-02 line pins).
- `! grep -- -SNAPSHOT` over the three published POMs (parent, `morimail`, `morimail-html`), the projects the deploy builds with `-pl morimail,morimail-html -am`. The sample POM is not deployed, so the guard skips it. On a match, grep prints the offending file and line, so no extra message is needed. `help:evaluate` is not used: it is slow, needs Maven, and the orchestrator ruled it out.
- The guard never goes into a warm-up block. Lines pasted after the gpg line would land in the pinentry prompt (04-05).
- The note says what the plugin does and does not mention the 401. The doc stays a general checklist.
- No rehearsal re-run (D-14). The deploy lines and every build input are unchanged, and this plan runs no deploy.
