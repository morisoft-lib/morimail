## Phase Goal

**As a** repository owner, **I want to** get the setup guide, final docs and a release rehearsal shaped by the live test, **so that** I can set up my tenant and publish 0.1.0.

Purpose: the code, the spec and the architecture page all agree with the real responses. A consumer's failure messages never carry the start of an address.

Choices (Claude's discretion, recorded here):
- WR-01 is fixed with the word-boundary cut, not by replacing addresses before the cut. A replace on the uncut text would run the address pattern over the whole server text again. The pattern is quadratic on a long word without "@", and the code comment explains that this is why the cut comes first (RESEARCH Pitfall 5).
- The test input from RESEARCH (990 "x", a space, then the address) cannot prove the fix. Measured at planning time, the old code also gives 300 "x" plus dots for it, because the final 300-character cut hides the leftover. The input used here shrinks the first word through the address replacement, so the old code leaves "aliceal" in the message. A reproduction of both clean() versions on 2026-11-22 showed `<address> aliceal` for the old code and `<address>` for the new code, in both packages.
- With the word-boundary cut, a single word longer than 1000 characters keeps nothing and gives "-". That is the safe loss the review accepts. The two existing @Timeout(10) tests feed such a word ("a" x100000 and "x" x100000), so their expected text changes to "-" while they stay quadratic-time guards. This is the only change to existing expectations.
- Spec edits: §6.3 (D-01) and the last paragraph of §8.3, which tells the reader to "adjust the default and this paragraph" after milestone 4. §12 is left as it is, because the owner's confirmations are already recorded in STATE.md and 03-UAT.md (Rule 0).

Output: the edited files in files_modified, three task commits and `04-01-SUMMARY.md`.
