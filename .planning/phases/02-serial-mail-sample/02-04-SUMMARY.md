# Phase 2 Plan 04: The owner dry-runs the shipped example campaign from the runnable jar Summary

**Runnable `morimail-sample-serial` jar (manifest classpath over `target/lib`) that dry-runs the shipped example campaign, five example.org rows with three placeholders, a PDF and a PNG, into five rendered mails with no secret set.**

## Accomplishments
- The sample POM builds a runnable jar: `maven-jar-plugin` manifest with `mainClass`, `addClasspath` and `classpathPrefix lib/`, plus a `copy-lib` execution of `copy-dependencies` (runtime scope). `target/lib` holds exactly jackson-annotations, jackson-core, jackson-databind, morimail and picocli. No version is repeated and no shade plugin is used.
- The example campaign ships `subject.txt`, `body.html`, `body.txt` (placeholders firstName, city, topic), `recipients.csv` (anna, ben, clara, david, emma at example.org; a quoted field, an ampersand and umlauts), and an `account.properties` with zero GUIDs, a newsletter address at example.com and environment-variable names only.
- One `.gitignore` negation tracks only the example account file; any other `account.properties`, `journal.jsonl` and `out/` stay ignored.
- `info.pdf` (602 bytes, PDF 1.4, no document information dictionary) and `logo.png` (240 x 120, 60959 bytes, only IHDR, IDAT, IEND) were generated once by a throwaway Python standard-library script outside the repository; no generator is in the repository or the build.
- From the jar, `send --dry-run` exits 0 with `MAIL_CERT_PASSWORD` and `MAIL_CLIENT_SECRET` unset, writes 15 files named 01- to 05-, and prints `attachments: info.pdf (application/pdf, 602 bytes), logo.png (image/png, 60959 bytes)` first. A real run exits 2 with the graph-not-available text and leaves no journal; `send --bogus` exits 2.
