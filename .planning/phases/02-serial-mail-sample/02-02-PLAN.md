# Phase 2 Plan 02: A broken campaign is rejected before the first send, with every problem at once

## Phase Goal

**As a** campaign sender, **I want to** dry-run and send a CSV serial mail with a journal, **so that** a rerun never mails a recipient twice.

This plan's slice: before any mail leaves, the sender sees every problem of a broken campaign in one report and gets exit code 2. Plan 02-01 created the command, the pre-flight list and the readers; this plan adds the checks that turn them into a complete pre-flight: placeholders against columns, the semicolon header, duplicate addresses, the remaining CSV structure rules and the account file's credential rules.

## Acceptance Criteria

- [ ] A broken campaign (placeholder without column, invalid address, duplicate, failing validate) prints all four problems in the fixed order and exits 2 with nothing sent and no journal.
- [ ] A `;`-delimited header is reported in the same run as the account-file, header and placeholder problems, not on its own.
- [ ] Every CSV edge case of RESEARCH Pattern 2 is pinned by a test.
- [ ] The account file accepts exactly one credential form, reads strict UTF-8 and never echoes a value.

## Flagged assumptions

- **Unclassified probe item CLI-02 (left unresolved).** Reviewed: unknown keys in account.properties are ignored without a warning (Rule 0); a misspelled credential key surfaces as the "no credential" problem. Open: whether the owner wants unknown keys reported.
- **Unclassified probe item CLI-04 (left unresolved).** Reviewed: the reader is lenient where RFC 4180 is strict: text after a closing quote is appended to the field, and a double quote inside an unquoted field is literal data. Open: whether either should be a pre-flight problem instead.
- **Placeholder fill for missing columns.** A placeholder without a column is reported once per file; the rows are then built with that name set to an empty value so their other problems still show. Those mails are never sent, because pre-flight has already failed.
- **Success criterion 2 and the `;` header.** A `;`-delimited header is one problem among the others, not a stop of pre-flight. The header rules and the placeholder check still run, against the header cells exactly as the comma reader read them, and the CLI-argument, account-file and campaign-file problems are reported in the same run. Only the rows are not analysed (RESEARCH Pattern 2: under a misread header every row only adds noise, and without an email column no row can be built), so no field-count, duplicate, row-build or `mailer.validate` problem can be determined for such a file. Because the checks see the comma reading, the header `email;firstName;city` also gives the missing-email-column problem and one placeholder problem per name; the `;` line comes first and names the cause. No second reading of the header split at `;` is added (Rule 0). `brokenCampaignReportsEveryProblemTogether` proves the placeholder, duplicate, invalid-address and validate problems together; `semicolonHeaderIsReportedWithEveryOtherProblem` proves the `;` problem together with an account-file problem, the email-column problem and the placeholder problems.
