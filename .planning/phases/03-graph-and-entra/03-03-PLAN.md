# Phase 3 Plan 03: A complete Graph sendMail request, with options checked and oversized mails rejected before sending

## Phase Goal

**As a** Java developer, **I want to** send mail through Microsoft Graph as an Entra app, **so that** each failure says whether to retry, drop the mail or fix the account.

This plan's slice: the request half of Graph. After it, a developer's mail goes to Graph with every recipient kind, names, both body rules and file attachments, the options are checked, and oversized mails are rejected before any byte is sent. It builds on the minimal transport from plan 03-01 and runs in the same wave as plan 03-02 (Entra), sharing no file with it. Plan 03-04 then completes the response half (the error mapping and the 401 retry) in the same two graph classes. All tests use a stub TokenProvider, as spec §10.1 asks.

## Acceptance Criteria

- [ ] The request URL, headers and JSON body (attachments and saveToSentItems included) are pinned against WireMock.
- [ ] The provider rejects unknown or mistyped options and a missing TokenProvider, naming the key and never the value.
- [ ] The 3 MiB and 4 MiB rules hold at every boundary and reject before sending.

## Flagged assumptions

- **No `from` in the body (RESEARCH Open Question 2).** The mailbox in the URL is the sender; the recipient-visible display name is a live-test item for the STOP report.
- **JSON allowance of 16 KiB (RESEARCH Assumption A5).** It covers subject, addresses and JSON syntax for normal mails; a mail with hundreds of recipients could exceed it, in which case Graph's own 413 maps to PermanentMailException.
- **The 4 MiB ceiling is community-sourced (RESEARCH Spec vs Docs row 2, Assumption A9).** It is one constant; plan 03-05 records the source in docs/architecture.md.
- **A file can change between validate and send.** `Mailer.send` runs validate right before send; the bytes read at send time are what is sent, and no lock is taken on files (edge GRAPH-05/concurrency).
- **Unclassified probe item GRAPH-03 (left unresolved).** Reviewed: name is `Attachment.filename()`, contentType is `Attachment.contentType()` (build() already defaults it to application/octet-stream), contentBytes is standard base64 with padding. Open: how Graph treats non-ASCII file names is not probed; JSON carries them as UTF-8.
- **Unclassified probe item GRAPH-04 (left unresolved).** Reviewed: `saveToSentItems` must be a Boolean, so the String "false" is rejected, matching the spec §5.1 usage `.option("saveToSentItems", false)`. Open: none known.
- **Split from the error mapping (plan-checker scope_sanity).** The response handling that used to be this plan's third task is plan 03-04, which runs after this plan because both change GraphTransport.java. Until plan 03-04 lands, send keeps the first-cut status mapping of plan 03-01; that is a missing branch, not a different shape.
- **Canon referral (dropped as a prohibition, owned by ASVS V5):** URL-path injection through the sender address; covered by the percent-encoding from plan 03-01, the address checks of build(), and T-03-13 below.
