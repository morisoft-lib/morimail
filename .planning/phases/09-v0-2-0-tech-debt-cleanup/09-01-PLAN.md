# Phase 9 Plan 01: core cid: rules and the three pattern copies (D-01 to D-09)

## Phase Goal

Close the open tech debt found by the v0.2.0 milestone audit, so the milestone can be archived with no known loose ends. This plan closes the Phase 5 core items: WR-01 (control characters in an echoed `cid:` id), WR-02 (the whole-HTML scan, closed by the `<` terminator and a documented trade-off), IN-01 (image types outside the table) and IN-03 (case-sensitive ids, documented).

Spec-less probe fallback: skipped, visibly. The phase has no requirement IDs (ROADMAP "Requirements: TBD"), so there is nothing to probe; the CONTEXT decisions D-01 to D-17 are the contract and every one is cited below.

## Acceptance Criteria

- [ ] `<p>cid:logo</p>` resolves to `logo` in the core, the sample copy and the helper copy, and the three pattern lines are identical (D-04, D-05).
- [ ] A recipient value with `cid:` and control, separator or format characters fails build() with the cleaned message and none of the raw characters (D-01, D-03); D-02 is checked and recorded.
- [ ] The `/>` rule is pinned and documented (D-06); no planning decision number is left in the pattern comments (D-07).
- [ ] webp, bmp and svg resolve from both tables (D-08); the case note is in the inline() Javadoc and the architecture row (D-09).
- [ ] Offline verify and the scoped release build are green after each commit, each commit has the maintainer identity and the trailer, nothing is pushed.
