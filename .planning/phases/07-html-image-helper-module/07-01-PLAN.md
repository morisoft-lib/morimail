# Phase 7 Plan 01: The morimail-html module and local images end to end

## Phase Goal

A template author can write ordinary image URLs in an HTML template, and one call to `HtmlImages` turns them into `cid:` references plus inline images that pass the Phase 5 checks.

This plan's slice: Task 1 (tracer) creates the module, wires it into the reactor, the release build and CI, and sends a template with two local images through `Mailer` to `recording` (HTML-01, HTML-06). Task 2 pins every rule for local sources and content IDs (HTML-02, HTML-03, HTML-04). Task 3 is the owner's early Temurin 17 round-trip, which also proves the new CI release line. Plan 07-02 adds downloads, Plan 07-03 the storable `data:` form, the module-boundary test `ModuleRulesTest` and the phase gate.

## Acceptance Criteria

- [ ] `HtmlImages.embed(template, baseDir)` rewrites local `<img src>` values to `cid:` references and returns the inline images; a converted template sent twice to `recording` passes `build()` both times.
- [ ] Outside, missing, unreadable, non-image and invalid local sources fail with `InvalidMailException` naming the `src` as written; `cid:`, `data:`, `http(s):`, unknown schemes and `$$` sources stay unchanged.
- [ ] `morimail` is untouched (no diff, no mention of the helper, Jackson-only tree); `morimail-html` has `morimail` as provided and nothing else outside test scope; the scoped release build with both modules is green and CI runs it.
- [ ] The owner's Temurin 17 CI run of the pushed 07-01 commits is green in all three steps before Plan 07-02 starts.

Flagged assumptions (research open questions, resolved with the research recommendation; the SUMMARY lists them under "Owner review"):
- A1: the scheme pattern needs one or more characters, `^[A-Za-z][A-Za-z0-9+.-]*:`, so `C:\img\logo.png` has the unknown scheme `c` and stays unchanged. This is the outcome D-09 states; D-09's reason ("two or more characters") would make it a failing local path.
- A5: `<img src="">` counts as a local src. It resolves to the base directory itself and fails with `img src "": is not a readable file`.
- A7 (HTML-01 probe row, unclassified): only the scoped release line `./mvnw -B -ntp -Prelease clean verify -Dgpg.skip -pl morimail,morimail-html -am` is supported. Planner choices (Claude's discretion per 07-CONTEXT.md; listed in the SUMMARY for owner review):
- P1: an image type must match `(?i)image/[a-z0-9][a-z0-9.+-]*` in full. Besides the `image/` prefix of Phase 5 D-10, the subtype may use only letters, digits, `.`, `+` and `-`. Every type the core table and common systems give passes (png, jpeg, gif, webp, svg+xml). Remote and `data:` types (Plans 07-02, 07-03) can then never carry a quote, an angle bracket or `$` into the HTML or into the `Attachment`.
- P2: for a local file, the ID base, the attachment file name and the table lookup use the file name of the real path (after `toRealPath`). A symlink alias inside the base directory therefore gets the target's name.
- P3: the public parameters are named `template`, `baseDir` and `workDir` (D-04 writes `t`); the class, method and record names are as in D-04.
- P4: no `package-info.java` (the core has none and doclint passes without it, Rule 0).
- Messages have the fixed form `img src "SRC": REASON` with SRC exactly as written in the template (before `&amp;` decoding). Local reasons: `base directory not found`, `is not a valid path`, `file not found`, `is outside the base directory`, `is not a readable file`, `is not an image file (content type TYPE)` with TYPE the resolved type or `unknown`.
