# Phase 9 Plan 02: pre-flight validates every mail (D-10 to D-12)

## Phase Goal

Close the open tech debt found by the v0.2.0 milestone audit, so the milestone can be archived with no known loose ends. This plan closes the Phase 6 (sample) item: pre-flight validates only the first mail against the Graph limits (SendCommand.java line 210 at 58ad024), so a later row with a larger substituted body passes pre-flight and fails at send time as a per-row failure.

Spec-less probe fallback: skipped, visibly. The phase has no requirement IDs (ROADMAP "Requirements: TBD"); the CONTEXT decisions D-10 to D-12 are this plan's contract.

## Acceptance Criteria

- [ ] Every non-null built mail goes through mailer.validate in pre-flight, and identical messages are one problem line with their row lines (D-10).
- [ ] A campaign with a passing first row and a failing later row stops in pre-flight with exit 2, names that row's line and sends nothing (D-11).
- [ ] Spec §8.3 step 2 says every row; the README and the help text were checked and need no change (D-12).
- [ ] Offline verify is green after both commits; both commits have the maintainer identity and the trailer; nothing is pushed.

<objective>
Replace the single validate call of SendCommand's pre-flight with a loop over every built mail that groups the validate messages by row line through the existing invalidMail helper (D-10), test it with the real Graph transport, whose validate is local, for a later-row failure and for a limit every row shares (D-11), update the existing recording-transport expectation, and bring spec §8.3 step 2 in line (D-12).

Purpose: a serial run must not start sending when a later row cannot be sent; all problems are reported together before the first send (spec §8.3 step 2). No new option, transport hook or test seam (Rule 0): `Mailer.validate(Mail)` already exists and `GraphTransport.validate` only reads file sizes and estimates the body.

Output: two commits and `09-02-SUMMARY.md`.

Choices (Claude's discretion, recorded here):
- Wave 2 after 09-01, not in parallel with it, although no file overlaps: two parallel branches would need a merge commit, the repository history has none, and a merge made under the workspace GIT_* variables would carry the wrong identity. 09-01 also changes Campaign.CID_REFERENCE, which SendCommand's dry-run uses; none of this plan's expectations depend on it.
- The later-row test uses the real `graph` transport. RecordingTransport.failValidation fails every mail, and MailAccount takes a transport id, not an instance, so "only a later row fails" cannot be expressed with `recording` without a new seam (09-RESEARCH.md finding 2).
- The Graph test account points at `http://localhost:1/v1.0` (the provider accepts http for localhost) with a counting token provider. Pre-flight must stop before any send; if it did not, the run would reach only a refused local port, never Microsoft. The planning rehearsal ran the new tests against the old SendCommand: they failed in under a second with exit 1 instead of 2, and no external host was contacted.
- The later-row message holds the computed size, so the test checks its fixed prefix and suffix, not the number.
- validate runs for rows beyond `--limit` as well, the same as the existing build loop; not special-cased.
