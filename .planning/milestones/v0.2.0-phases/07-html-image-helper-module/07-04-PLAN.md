# Phase 7 Plan 04: `morimail` in compile scope for `morimail-html` (gap G-07-2)

## Phase Goal

A template author can write ordinary image URLs in an HTML template, and one call to `HtmlImages` turns them into `cid:` references plus inline images that pass the Phase 5 checks.

This plan's slice comes from UAT test 2 in 07-UAT.md. The owner decided that `morimail-html` declares `morimail` in compile scope, which reverses D-02's earlier choice. Maven's nearest-wins rule already lets a consumer's own `morimail` dependency win. The earlier scope gained nothing for a consumer who declares `morimail`, and it left the helper's published POM without a link to a core version that has inline-image support. This plan changes the scope and brings every current text that states the old scope in line. It writes no new code.

## Acceptance Criteria

- [ ] `morimail-html/pom.xml` declares `morimail` in compile scope (no scope element), and the dependency gates show the runtime classpath `morimail` plus Jackson through `morimail`, with no `morimail-html` in the core's tree.
- [ ] `docs/architecture.md`, the `ModuleRulesTest` Javadoc and `07-CONTEXT.md` (dated amendments to D-02 and D-03) say compile scope. No older 07 file is rewritten.
- [ ] The offline verify and the offline scoped release build are green, the `morimail` jar equals the one built from f9b2f57, and two maintainer commits exist and are not pushed.
