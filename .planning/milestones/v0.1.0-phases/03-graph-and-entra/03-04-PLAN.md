# Phase 3 Plan 04: Every Graph failure maps to the right category, after one retry with a fresh token on a 401

## Phase Goal

**As a** Java developer, **I want to** send mail through Microsoft Graph as an Entra app, **so that** each failure says whether to retry, drop the mail or fix the account.

This plan's slice: the response half of Graph. After it, every answer from Graph, the 401 retry included, ends in the documented exception, and the message carries Graph's status, code, request-id and cleaned message but never a token, a body or an address. It builds on the complete request of plan 03-03 and changes the same GraphTransport.java, so it runs after it, alone in wave 3. The sample plan 03-05 waits for it. All tests use the StubTokenProvider of plan 03-03, as spec §10.1 asks.

## Acceptance Criteria

- [ ] A 401 is retried exactly once with the fresh token and then mapped by the mailbox hint.
- [ ] Every row of the §6.3 table plus the D-06 class rule maps to its exception, with Retry-After where given, and no request is ever repeated except after a 401.
- [ ] Messages carry status, code, request-id and the cleaned Graph message, survive hostile bodies, and never carry a token or body; network errors and timeouts are transient.

## Flagged assumptions

- **Split from plan 03-03 (plan-checker scope_sanity).** This plan is the former third task of the Graph plan, divided into a tracer and two expansions. It runs alone in wave 3 because it changes GraphTransport.java after plan 03-03.
- **Retry-After dates are compared with `Instant.now()`.** The transport has no clock seam (Rule 0). The tests use a date far in the future and one far in the past, so no test depends on the wall clock to the second.
- **A redirect is PermanentMailException.** Redirects are never followed (plan 03-01), so a 3xx reaches the D-06 class rule like any unlisted status. The live test can correct it.
- **Parsing and cleaning are duplicated by intent.** `retryAfter` and `clean` also exist in the Entra token client of plan 03-02. The two packages must not reference each other (D-10, Claude's Discretion), so about 25 lines are duplicated.
- **Unclassified probe item GRAPH-07 (left unresolved).** Reviewed: one fresh-token retry, then `mailboxHint` on error.code only (never error.message, per the Graph errors page). Open: which code the real service returns for an unlicensed or missing mailbox (RESEARCH Assumption A7) is a STOP-report item.
