# Phase 2 Plan 04: The owner dry-runs the shipped example campaign from the runnable jar

## Phase Goal

**As a** campaign sender, **I want to** dry-run and send a CSV serial mail with a journal, **so that** a rerun never mails a recipient twice.

This plan's slice: on a fresh clone, the owner builds the sample, starts the runnable jar and dry-runs the shipped example campaign into five rendered mails, with no secret environment variable set. It builds on the command and the dry-run writer of plan 02-01 and runs in wave 2 next to plans 02-02 and 02-03, sharing no file with them. This plan was split out of plan 02-01 (former Task 3) so that no plan of the phase lists 15 or more files.

## Acceptance Criteria

- [ ] The runnable jar dry-runs the shipped example campaign into 5 mails named 01- to 05- with no secret environment variable, and a real run from the jar stops with the D-01 message and exit 2.
- [ ] The example campaign has three placeholders, five example.org rows, an example-only account file tracked through one .gitignore negation, and a PDF and a PNG under 100 KB with no identity metadata.
- [ ] The scoped hygiene gates pass over the sample module, .gitignore and the phase directory.

## Flagged assumptions

- **Attachment generator stays outside the repository (discretion).** The PDF and PNG are generated once by a throwaway Python standard-library script in a temporary directory; the committed bytes are the source of truth, and no generator enters the repository or the build.
- **Structural PDF check only.** No PDF tool is installed here, so ExampleCampaignTest checks the PDF structure (header, xref offsets, no information dictionary); whether a real viewer opens it is the human check at the end of Task 2.

## Artifacts this phase produces

Created by this plan:

- Files: `morimail-sample-serial/example-campaign/` with `account.properties`, `subject.txt`, `body.html`, `body.txt`, `recipients.csv`, `attachments/info.pdf`, `attachments/logo.png`; the `.gitignore` negation line `!morimail-sample-serial/example-campaign/account.properties`; in the sample POM the build section with the jar manifest (`mainClass`, `addClasspath`, `classpathPrefix lib/`) and the `copy-lib` execution of `copy-dependencies`.
- Test class `ExampleCampaignTest` (`dryRunWritesFiveRenderedMails`, `usesThreePlaceholdersAndFiveExampleRows`, `accountFileHoldsOnlyExampleValues`, `attachmentsAreSmallAndCarryNoMetadata`).

Created by the other plans of this phase: the command, readers, journal, dry-run writer, `SampleFixtures` and the picocli dependency (plan 02-01); the placeholder, semicolon-header, duplicate and credential-form checks (plan 02-02, same wave); retry, stop, the argument checks, exit code 3, the `transient` outcome and journal robustness (plan 02-03, same wave). The full list is in 02-01-PLAN.md under the same heading.
