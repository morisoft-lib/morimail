# Phase 2 Plan 03: Retry, stop, pacing and a journal that survives a crash

## Phase Goal

**As a** campaign sender, **I want to** dry-run and send a CSV serial mail with a journal, **so that** a rerun never mails a recipient twice.

This plan's slice: a real run behaves correctly when the mailbox pushes back. A transient failure is retried with capped waits, a sender or auth failure stops the run with exit 3, sends are paced by `--rate`, `--limit`, `--campaign-id` and `--journal` behave as specified, and the journal stays usable after a crash or a failed write. It builds on the command from plan 02-01 and runs in the same wave as plan 02-02, sharing no file with it.

## Acceptance Criteria

- [ ] Transient failures are retried with the D-09/D-11 waits, at most four attempts per row, each attempt journaled.
- [ ] A sender-rejected or auth-required failure stops the run at once with exit 3; a rerun resumes.
- [ ] Spacing, skipped rows, `--limit`, `--campaign-id`, `--journal` and the argument problems are pinned by tests.
- [ ] A damaged journal line is warned about and resent, and a failed journal write stops the run with exit 1.

## Flagged assumptions

- **Pre-flight ignores --limit (RESEARCH Open Question 1).** Spec 8.3.2 says "every row has a syntactically valid email", so pre-flight checks the whole CSV even with `--limit 1`. A bad row after the limit therefore blocks a `--limit 1` verification run. Reversible in SendCommand if the owner prefers to check only the processed rows.
- **Counts on a stop (RESEARCH Open Question 4).** The row that caused the exit-3 stop counts as failed and has a failed journal line; later rows are not counted.
- **Counts on a journal write failure.** The counts line shows only journaled outcomes; the row whose line could not be written is not counted, and the stderr line says that its mail may have been sent.
- **Damaged journal lines (RESEARCH Assumption A3, Open Question 5).** Warned and ignored, so the row is sent again (at-least-once); never a pre-flight stop, so a crash never needs a manual journal edit.
- **Unclassified probe item CLI-08 (left unresolved).** A transient failure that never clears costs up to four attempts with waits of up to five minutes each per row; there is no time budget for a whole run.
- **Unclassified probe item CLI-09 (left unresolved).** Reviewed: the stop happens on the first sender-rejected or auth-required failure, even if later rows use another sender (all rows share one account here). Open: none known.
- **Unclassified probe item CLI-10 (left unresolved).** Progress lines go to stdout and stop or warning lines to stderr through picocli's writers; when both streams go to one terminal or pipe, their relative order is not guaranteed.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI to the mail service (through the Mailer) | every attempt can be throttled, rejected or lost; the run must not hammer the mailbox |
| journal file across runs | written by one run, read by the next; may be torn by a crash or edited by hand |
| CLI to the console and CI logs | progress, stop and warning lines are printed and may be captured |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12 | Repudiation | Journal.append | medium | mitigate | One forced line per attempt (force(true)); a failed write stops the run with exit 1 and says the last mail may have been sent; JournalTest proves the stop with /dev/full |
| T-02-13 | Tampering | Journal.open | medium | mitigate | A damaged, torn or forged non-object line is warned about and never counts as accepted, so no recipient is silently skipped; the line-feed repair keeps later records parseable |
| T-02-14 | Denial of Service | SendCommand attempt loop against the mailbox | medium | mitigate | Spacing ceil(60000 / rate) ms before every attempt, retries included; retryAfter capped at 5 min but never below the spacing; at most 4 attempts per row; the run stops at once on sender-rejected or auth-required, so a locked account is not retried row after row |
| T-02-15 | Information Disclosure | journal and console error text | low | accept | Only the exception class and message are written; library messages never carry tokens or bodies (GRAPH-08 in Phase 3, ERR rules in Phase 1); the journal stays git-ignored |
| T-02-16 | Repudiation | a mail in flight when the process is killed | low | accept | At-least-once is the owner's recorded decision; the help footer states it and the forced per-attempt journal narrows the window |
| T-02-SC | Tampering | Maven artifacts | high | mitigate | This plan changes no POM and adds no dependency |
