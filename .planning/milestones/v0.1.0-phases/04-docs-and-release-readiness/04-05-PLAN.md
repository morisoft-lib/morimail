# Phase 4 Plan 05: gpg-agent warm-up and signing-failure hint in docs/release.md (gap G-04-3)

## Phase Goal

**As a** repository owner, **I want to** get the setup guide, final docs and a release rehearsal shaped by the live test, **so that** I can set up my tenant and publish 0.1.0.

This plan's slice is DOCS-04 and roadmap success criterion 5, which says the owner's release steps are listed. In UAT test 3 the owner followed docs/release.md step 5. The deploy failed with `maven-gpg-plugin:3.2.8:sign (sign-artifacts) on project morimail-parent: Exit code: 2`, and nothing was uploaded. The diagnosis is in `.planning/debug/release-doc-gpg-signing.md`. Under `-B` the plugin runs gpg with `--batch --no-tty --pinentry-mode error`, so only a passphrase that gpg-agent has already cached can sign. The doc has no step that fills that cache. It promises a prompt that cannot happen, and it offers `GPG_TTY` as the remedy. This plan corrects the doc and nothing else.

- [ ] The 04-04 release.md gate still passes, and no build input changed since the release commit 72e7f7f.
- [ ] `./mvnw -B -ntp verify` is green. The commit is docs/release.md only, made as the maintainer with the trailer, and not pushed.
