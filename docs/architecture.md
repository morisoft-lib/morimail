# morimail architecture

This page summarises the contracts of morimail and the reasons for them. The full contract summary follows with the 0.1.0 documentation. Deviations from the spec are recorded here as they are made (spec §5: signatures are binding in intent).

## Deviations from the spec

| Spec | morimail | Reason |
|------|----------|--------|
| §7.3 (do not widen `TokenProvider`) | `TokenProvider` has a default method `freshAccessToken(String scope, String rejectedToken)` that delegates to `accessToken(scope)`. | The Graph transport can get a new token after a 401 without importing `entra`. Lambdas still work, and there is no new interface (CORE-02, owner decision). |
| §5.3 (data is `Map<String, Object>`) | `Mail.Builder.template(MailTemplate, Map<String, ?>)`. | Typed maps such as a CSV row `Map<String, String>` compile. Values still go through `String.valueOf` (D-02a, owner decision). |
| §2 and §5.1 (error types unspecified) | An unknown transport id raises `IllegalArgumentException` that lists the available ids. A duplicate or blank provider id and a broken provider raise `IllegalStateException`. Invalid account configuration raises `IllegalArgumentException`. | Configuration errors surface when the account or registry is built and are not mail errors. The checked `MailException` tree stays for sending. |
| §3 (JUnit 5) | JUnit Jupiter 6.1.3 through `junit-bom`. | It is the current stable line, with the same `org.junit.jupiter` API and a Java 17 baseline (D-02c, owner decision). |
| §10.1 (published as a test-jar) | The test-jar with `RecordingTransport` is built and shared inside the reactor only. The release profile sets `attach false` on it. Because an unattached test-jar is invisible to a packaging reactor, the release build runs on the published modules only (`-Prelease ... -pl morimail -am`). | The Central plugin would otherwise stage the test-jar, and spec §13.2 says the test-jar is not published (owner decision). |
| §7.1 (authority as a constructor option) | `EntraClientCredentials.authority(URI)` is a copy method that returns a new instance. The factories keep the spec signatures. | One way to point the token endpoint at a test server without a builder or overloads (D-01). |
| §7.2 (PKCS12 password) | The password is a `char[]`. The file must hold exactly one RSA key entry with its certificate. Any key-store problem is an `IllegalArgumentException` that names the file and never the password. | `KeyStore.load` convention, and a setup error is not a mail error (D-03 to D-05). |
| G1 (timeouts) | The connect timeout (10 s) and request timeout (30 s) are fixed private constants in `entra` and `graph`. No option sets them. | Rule 0. They can become settable later without a break (D-02). |
| §6.1 (options) | The `graph` transport takes a second option, `baseUrl`, next to `saveToSentItems`. Unknown keys, a non-Boolean `saveToSentItems`, a `baseUrl` that is not an absolute https URL (http is accepted for `localhost`, `127.0.0.1` and `[::1]` only) and a missing `TokenProvider` are `IllegalArgumentException`s that name the key. The scope stays `https://graph.microsoft.com/.default`, so sovereign clouds need more work than a base URL. | Tests and the sample point the transport at WireMock (D-11). |
| §6.2 (3 MB, 4 MB) | "3 MB" is 3 x 1024 x 1024 bytes, per file and in total. The 4 MiB request limit is an estimate: base64 size of the attachments, the body as the JSON-escaped UTF-8 bytes that `send` writes, and a 16 KiB allowance. A file just under 3 MiB therefore fails the estimate, not the per-file rule. | Both are checked in `validate`, before any token request (D-08, D-09). |
| §6.3 (error table) | Statuses not in the table follow a class rule: 5xx transient, every other 4xx, 1xx and 3xx permanent. Redirects are never followed. A second 401 after the fresh-token retry is `SenderRejectedException` when `error.code` contains `mailbox` (case-insensitive), else `AuthRequiredException`. | One rule instead of a list, and one place for the live test to correct (D-06, D-07). |
| §6.3 (failure message) | A Graph failure message carries the HTTP status, the cleaned `error.code` and the `request-id`, nothing else. Graph's free-text `error.message` is never read into it. | In the live test, Graph's text for a 404 `ErrorInvalidUser` named the sender. The address reached the exception message and the live test output, and it would also reach the sample's stop line and journal. A pattern that replaces addresses in free text cannot be relied on, so the text is left out (UAT G-03-2). This narrows GRAPH-08. |
| §6.3 and §7.3 (`Retry-After`) | `Retry-After` is read as seconds only, in `graph` and in `entra`, with the code written twice on purpose. Anything else, an HTTP date included, gives none. | `graph` and `entra` must not import each other (D-10). |
| §7.3 (token errors) | Every 4xx except 429, every 3xx and an unusable 200 (not JSON, no `access_token`, no positive `expires_in`) is an `AuthRequiredException`. 429, 5xx and network errors are transient. | The documented error is a 400, but other 4xx are possible, and a token that cannot be used cannot be retried into success. |
| §10.1 (test key store) | The key store is `morimail/src/test/resources/test-keystore-throwaway.p12`, password `changeit`, legacy PKCS12 (`keytool -J-Dkeystore.pkcs12.legacy`). | `keytool` rejects passwords shorter than six characters, and the legacy format loads on every JDK 17 patch level. |
| §10.1 (one live test) | The live test is one class, `LiveGraphTest`, with a main test and two opt-in probe methods (out-of-scope mailbox, big attachment) that are skipped unless their variable is set. It is excluded by tag and run with `-Plive`. | One run answers the STOP report items; each probe prints one line the owner can paste (D-16). |

## Contracts

- `Mail.Builder.build()` checks that attachment files exist and are readable, but a file can still disappear before the transport reads it. A transport reports an attachment it cannot read at send time as an `InvalidMailException` that names the file and never carries its content.
- The Graph transport sends a request once and retries only after a 401, with a fresh token. Every other failure is mapped and thrown; retries, backoff and queues belong to the consumer.
- `entra` writes no log records. `graph` writes one fixed INFO record per transport when a mail has both an HTML and a text body. Exception messages never carry tokens, secrets, assertions or mail bodies. A Graph failure message holds only the HTTP status, `error.code` and `request-id`, never Graph's free-text message (G-03-2); those fields are identifiers in practice. An Entra failure message quotes `error` and `error_description` (spec §7.3). These service fields are cleaned of control characters, cut at 300 characters, and have anything that looks like a mail address replaced by `<address>`. That pattern is a best-effort safeguard, not a guarantee; the Entra description can still name the application and tenant ids.

## Differences from the Microsoft documentation

Read on 2026-11-22. Where a page differs from the spec, the library follows the page and the difference is listed here.

- One body: the message resource has a single `body` (HTML or text), so the transport sends HTML when present, else text. A mail with both is logged once; sending both would need MIME.
- 4 MiB request limit: not stated on the sendMail, errors, throttling or large-attachments pages. The only source is a Microsoft Q&A answer ("generally around 4 MB", then a 413). The constant is kept as an estimate.
- 3 MiB attachment limit: the large-attachments page names 3 MB for a single POST to a message's `attachments` property. The sendMail page states no attachment limit. The 3 MiB rule is conservative and applies to `sendMail` by inference.
- `saveToSentItems`: the sendMail page types it as Boolean ("specify it only if the parameter is false") but its examples show the string `"false"`. The library sends the JSON boolean `false`, and only when the option is false.
- Entra assertion: PS256, the `x5t#S256` header and the claims (`aud`, `iss`, `sub`, `jti`, `nbf`, `iat`, `exp`) match the certificate-credentials page. The client-credentials page still shows an RS256 sample assertion. There is no RS256 fallback; only the live test shows whether the service accepts PS256.
- Token response: the documented body has `access_token`, `token_type` and a numeric `expires_in`. The library reads only the token and a numeric `expires_in` (a string value makes the response unusable), clamps `expires_in` to one year and always sends `Bearer`.
- Token errors: the documented example is a 400 with `error`, `error_description` and more fields. Every 4xx except 429 is treated the same way.
- Error body: the errors page spells the inner error `innerError` in its example and `innererror` in its property table. The code reads both.
- `request-id`: the errors page does not name the response header. The code reads the `request-id` header first, then the inner error.
- `Retry-After`: the throttling page documents seconds only, and the library reads only seconds. An HTTP-date value is treated as absent.
- `from`: the message `from` property must match the mailbox in the URL, and changing it needs send-as rights, so the body carries no `from`; the mailbox is in the path.
- Limits: the Outlook service limits (10,000 requests per 10 minutes, four concurrent requests, 150 MB upload per 5 minutes per app and mailbox, 500 recipients per message) are far above a serial sender at 20 mails per minute. No code uses them.
- Character escapes in the size estimate: Jackson writes a character outside the Basic Multilingual Plane (an emoji) in a JSON string as a surrogate escape pair of 12 bytes, not as 4 UTF-8 bytes. Other non-ASCII characters such as an umlaut stay raw (2 bytes). The estimate measures the body with the mapper that `send` uses, so it counts what is posted.
- The mailbox error code for an unlicensed or missing mailbox is not documented. `error.code` containing `mailbox` is an assumption; the live test is where it gets corrected.
